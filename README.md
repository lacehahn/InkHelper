# 墨屏助手 InkHelper

墨屏助手是一个本地网络通知中继 Android 应用。它安装在两台 Android 设备上：主力手机作为“发送端”读取系统通知，墨水屏或备用手机作为“接收端”显示收件箱。MVP 不依赖云服务，核心链路只在同一个局域网内工作。

## 当前状态

- 一个 APK 同时支持发送端和接收端两种角色。
- 发送端通过 Android 通知监听服务读取可转发通知。
- 接收端通过局域网配对并接收通知。
- MVP 暂不做应用过滤：能读取且能形成标题或正文的通知默认都会转发。
- UI 已改为简体中文、黑白高对比、白色主基调，适合墨水屏阅读。
- 收件箱和发件箱支持单条删除、清空，以及常见应用名展示映射，例如 `com.tencent.mm` 显示为“微信”。
- 启动本地连接后会显示一个低打扰常驻通知，用于让 Android 将本地中继按前台服务运行；应用会请求该通知保持为不可清理的持续运行样式。

## 环境要求

- 两台 Android 设备，建议 Android 13 或以上。
- 两台设备处于同一个局域网，例如同一个 Wi-Fi，或接收端连接发送端手机热点。
- 发送端需要开启“通知读取权限”。
- 接收端需要开启系统通知权限，这样后台收到新消息时可以在状态栏和通知栏提醒。
- Windows 开发环境可使用仓库自带 Gradle Wrapper 构建。

## 构建 APK

在仓库根目录运行：

```powershell
.\gradlew.bat :app:assembleDebug --console=plain
```

生成的调试 APK 位于：

```text
app\build\outputs\apk\debug\app-debug.apk
```

也可以直接使用 Android Studio 打开项目并运行 `app` 模块。

## 安装

可以通过 Android Studio 安装，也可以通过 adb 安装：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

两台设备都安装同一个 APK。安装后分别选择不同角色：

- 主力手机：选择“发送端”
- 墨水屏或备用手机：选择“接收端”

## 发送端使用步骤

1. 打开墨屏助手。
2. 点击“设为发送端”。
3. 点击“启动发送端连接”。
4. 打开右上角“设置”。
5. 在通知读取权限不可用时，点击“开启通知读取权限”，在系统设置里允许“墨屏助手通知读取权限”。
6. 回到应用，确认监听服务状态为可用或已连接。
7. 保持发送端和接收端在同一个局域网内。
8. 启动发送端连接后，系统通知栏会出现“墨屏助手正在后台运行”的常驻通知。
9. 接收端配对成功后，新的系统通知会进入发送端“发件箱”，并尝试转发给接收端。

发件箱中的状态含义：

- “已确认接收”：接收端已校验并写入收件箱。
- “未确认”：发送端已尝试发送，但没有收到有效确认。
- “未发送”：当前没有可用连接，或通知未通过发送条件。
- “已拒绝”：接收端拒绝了该条数据。

## 接收端使用步骤

1. 打开墨屏助手。
2. 点击“设为接收端”。
3. 点击“扫描发送端”。
4. 在发现发送端后，点击候选地址进行配对。
5. 连接成功后，收到的消息会显示在“收件箱”。
6. 连接成功后，系统通知栏会出现“墨屏助手正在后台运行”的常驻通知。
7. 应用在后台运行时，收到新消息会通过系统通知提醒。

收件箱与发件箱都支持：

- 点击每条消息右侧的 `X` 删除当前列表中的这一条。
- 点击“清空”删除当前列表中的所有消息。

这些删除只影响墨屏助手本地展示列表，不会删除微信、QQ 或其它原应用里的通知和消息。

## 小米 / HyperOS 注意事项

在小米 14、HyperOS 等系统上，通知监听服务可能被系统限制。若发送端没有捕获到微信等通知，请检查：

1. 系统设置中已允许“通知读取权限”。
2. 应用详情中允许“受限设置”。
3. 后台运行、省电策略、自启动等限制已放宽。
4. 墨屏助手发送端保持为“发送端”角色，并已启动发送端连接。

如果权限看起来已开启但监听服务仍未连接，可以在发送端右上角“设置”中点击“重连通知监听服务”，或进入系统设置重新关闭再打开通知读取权限。

前台服务常驻通知不等于收到的新消息通知。常驻通知表示墨屏助手正在保持本地中继运行；收到微信、QQ 等转发消息时，接收端还会另外弹出对应的新消息通知。常驻通知会请求不可清理样式，但极少数系统或厂商策略仍可能允许系统层面隐藏或管理它。

## 双机网络建议

最稳定的 MVP 测试方式：

1. 主力手机开启热点。
2. 墨水屏或备用手机连接这个热点。
3. 主力手机运行发送端。
4. 墨水屏或备用手机运行接收端并扫描发送端。

如果使用普通 Wi-Fi，请确认路由器没有开启 AP 隔离、访客网络隔离或禁止局域网设备互访。

## 调试日志

项目使用 `InkHelper` 作为主要 logcat tag。连接或转发异常时可以查看：

```powershell
adb logcat -d -s InkHelper
```

常见关键日志包括：

- `sender_listener_notification_posted`：发送端监听到了系统通知。
- `sender_listener_notification_transfer_thread_start`：发送端开始在后台线程转发通知。
- `runtime_sender_outbox_changed`：发件箱状态发生变化。
- `transfer_sender_socket_write`：发送端已写入本地网络连接。
- `receiver_inbound_accept`：接收端接受了通知数据。
- `receiver_inbound_reject`：接收端拒绝了通知数据。

日志不会输出完整通知正文，避免把消息内容直接写入调试日志。

## MVP 限制

- 不提供云同步或互联网中继。
- 不保证断线期间自动补发历史通知。
- 不复制原通知的操作按钮、快捷回复、媒体控制或复杂布局。
- 当前收件箱和发件箱是本地展示状态，不是完整消息数据库。
- 当前安全模型只面向个人局域网研究使用，不声称可抵御恶意局域网或生产级攻击。
- 前台服务和 3 次自动重连只能降低后台中断风险，不能保证所有 Android 厂商策略下都不被停止。
